# v0.1.0 release preparation

**Draft: this document prepares the first companion release. It does not create
or announce a tag, published release or registry registration.** The package
metadata already says `0.1.0`; that version number alone is not a source pin.

The candidate source is
[`fe64588ccda4515a421f25a044b3b3081bd695fb`](https://github.com/Space-FALCON-Lab/SpaceAGORAMuJoCo.jl/commit/fe64588ccda4515a421f25a044b3b3081bd695fb).
This preparation adds documentation without changing runtime code, dependencies,
tests, installation behavior or the default core revision.

## What this release contains

SpaceAGORAMuJoCo is an optional repository for standalone MuJoCo proximity scenes
(Stage 1) and scenes that own spacecraft inside SpaceAGORA's `run_simulation`
(Stage 2). It contains the native binding, scene state/reset/step API,
`ProximitySceneDynamics`, adapter tests, independent installer and the Basilisk
comparison harness with its original third-party notices. Core does not depend
on or automatically load this companion.

The adapter connects through `SpaceAGORA.ExternalPropagationServices` contract
**1.0.0**. It verifies that exact contract before defining adapter methods and
again during package initialization. Configuration selects owners per run;
each run copies the scene template into its own mutable native runtime. The
[common adapter standard](https://github.com/Space-FALCON-Lab/SpaceAGORA.jl/blob/f9eb5f13cf2f19f4327abb358d22513960bef23f/docs/src/maintainer/adapter_contract.md)
and [service reference](https://github.com/Space-FALCON-Lab/SpaceAGORA.jl/blob/f9eb5f13cf2f19f4327abb358d22513960bef23f/docs/src/maintainer/external_propagation_services.md)
define the supported connection. Sharing this versioned-service pattern with
HYPR does not make their domain protocols interchangeable.

## Clean installation of the default pair

Prerequisites: Linux x86_64, command-line Git, `julia` pointing to Julia 1.12.3,
and network access to GitHub, Julia packages and the declared native artifact.
Run these commands from a writable directory. The new directory must not
already exist; the recipe uses its own environment and depot.

```sh
set -eu
julia --startup-file=no -e 'VERSION == v"1.12.3" || error("Use the tested Julia 1.12.3")'
release_dir="$PWD/spaceagora-mujoco-v0.1.0"
mkdir "$release_dir"
git clone https://github.com/Space-FALCON-Lab/SpaceAGORAMuJoCo.jl.git "$release_dir/companion"
cd "$release_dir/companion"
git checkout --detach fe64588ccda4515a421f25a044b3b3081bd695fb

export JULIA_DEPOT_PATH="$release_dir/depot"
export JULIA_LOAD_PATH='@:@stdlib'
export JULIA_NUM_THREADS=4
export OPENBLAS_NUM_THREADS=1
export JULIA_PKG_PRECOMPILE_AUTO=0
SPACEAGORA_CORE_PATH= SPACEAGORA_CORE_REV= \
  julia --startup-file=no scripts/setup_env.jl "$release_dir/environment"
julia --startup-file=no --project="$release_dir/environment" \
  -e 'using SpaceAGORA, SpaceAGORAMuJoCo; SpaceAGORA.ExternalPropagationServices.require_version(v"1.0.0")'
```

The installer fetches and verifies core `1d146eb5…` into
`environment/sources/SpaceAGORA-<full-SHA>`, develops both checkouts and creates
an independent manifest. It does not copy a parent manifest, call a HYPR
installer, initialize core submodules or hydrate core LFS assets. No licensed
GRAM data is required. A modified or mismatched setup-owned core checkout is
refused rather than reset. Keep the companion checkout, environment, managed
core source and depot available at these paths: the environment uses local
source paths. Installation and precompilation are explicit setup operations.

To repeat the isolation and native acceptance probes from that same shell:

```sh
julia --startup-file=no test/installation_plan_tests.jl
julia --startup-file=no test/source_acquisition_tests.jl
julia --startup-file=no --project="$release_dir/environment" test/core_only.jl
julia --startup-file=no --project="$release_dir/environment" test/incompatible_core.jl
julia --startup-file=no --project="$release_dir/environment" test/load_order.jl core-first
julia --startup-file=no --project="$release_dir/environment" test/load_order.jl companion-first
SPACEAGORA_MUJOCO_REQUIRED=1 julia --startup-file=no --project="$release_dir/environment" \
  -e '@assert Threads.nthreads() == 4; include("test/runtests.jl")'
```

The last command downloads the lazy MuJoCo artifact when necessary and runs the
native regression suite, including orbit comparisons and threaded Monte Carlo
checks. It is more than an import smoke test. A skipped native suite is not
acceptance. Python 3.11 or later plus NumPy are needed only for the separate
synthetic Basilisk-harness guards; see the [validation commands](../../README.md#validation).

## Platform, numerical and coupling limits

- The binding supports **MuJoCo 3.11.0 on Linux x86_64 only**. It checks the native
  version and uses offsets from that ABI. The [artifact declaration](../../Artifacts.toml)
  pins archive SHA-256 `681a9353b296a06682e9e757d6d21ab7a0a5a5bdb218a1c05cb9a38536817c79`
  and unpacked tree `6a34a368d528ad0332f9da97de3d2f105977bac8`. Windows, macOS and
  other architectures are not qualified. A native fault can end the process.
- Scene `dt` is explicit, finite and positive. Supported scene integrators are
  `:implicitfast` (default), `:implicit` and `:euler`; `:rk4` is rejected because
  the `mj_step1`/`mj_step2` path does not execute RK4 stages. Gravity wrenches are
  held across each scene step, so the coupled method is first order in `dt`.
  The chief's RK4 update does not make the complete scene method fourth order.
- Standalone scenes accept position-only static gravity effectors. J2 and
  harmonics need the supplied inertial-to-planet rotation. Scene state uses
  metres, seconds, radians and body-frame angular rates; quaternion component
  order differs between core and MuJoCo and is handled by the adapter.
- For Stage 2, every free-root body must map to one spacecraft. The scene's
  planet, gravity and mass model must agree with the intended run; core dynamic
  effectors are not applied to owned spacecraft. `mass_rtol` enables an explicit
  mass-consistency check; it is disabled by default. A scene template is copied
  per run, and paired spacecraft initial conditions replace its initial states.
- Stage 2 does not yet connect SpaceAGORA actuation, sensors or environment
  loads to scene bodies. Core control effectors targeting owned spacecraft are
  refused. Standalone scene controls and the comparison harness do not imply
  this Stage 2 connection exists.
- Core solver modes are limited to `:tsit5`, `:auto_stiff`, `:rodas5p` and `:dp8`.
  Checkpoint/resume, process-pool campaigns, `run_constellation_ensemble`, the
  flat RHS route, core articulated/compliant/robot-arm dynamics on an owned
  spacecraft, and unsupported continuous events are refused. Periodic GNC
  intervals must be integer multiples of scene `dt`. Impact detection is not
  applied to owned shadow entries. See the [architecture reference](../architecture.md)
  for the complete refusal and synchronization contract.

The existing orbit and Basilisk comparisons support their documented cases
and tolerances. They do not establish universal contact accuracy or a new
performance claim. The Basilisk harness's Case C remains explicitly
**inconclusive**; its remote wrapper retains lab-specific host configuration.
This release preparation reruns no scientific campaign and changes no numerical
model, tolerance or benchmark protocol.
